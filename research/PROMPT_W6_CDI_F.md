## 1. Architect's analysis (why this shape)

1. **Current corpus state:** W1–W5 workstreams integrated on `research/bootloader-flash` (`QUALITY_REVIEW.md` verdict PASS, 0 broken links). New work must not regress this. W6 provides the bootloader/flash base; this prompt adds the CDI-Flash sprint briefs and rule-sets.

2. **What's missing:** (a) systematic sprint briefs F1..F100 covering CDI flash topics across 8 phases — no existing corpus has this granularity of sprint-focused ASIL-relevant questioning; (b) CDI_FLASH rule-set for flash/bootloader-adjacent safety testing (power-loss, timing, secure-boot verification, anti-rollback, dual-bank update safety, HSM integration) — absent from current records; (c) V2-FLASH rule-set for evolved flash protocol with manufacturing/EOL traceability, UDS session transitions, power-transient handling, and OTA consistency checks — new tag set V2-FLASH-001..V2-FLASH-20; (d) per-brief AI-ready guideline IF/THEN/WITH/GATE and Lesson learnt fields, appended after the core schema (backward compatible with W6 field order).

3. **Design decision — one file, two additions:**
   - **Sprint briefs F1..F100** — 8 phases F1..F8, each with ~12-13 briefs (total 100). Each brief: ID, Topic, ASIL-relevant question, Domain, Target artifact (matrix/artefact/ref), Confidence, Unanswered, AI-ready guideline IF/THEN/WITH/GATE, Lesson learnt. Grouped by thematic cluster: F1..F12 (bootloader foundation), F13..F24 (secure update mechanics), F25..F36 (power-loss & timing), F37..F48 (anti-rollback & anti-tamper), F49..F60 (dual-bank & multi-bank update safety), F61..F72 (HSM integration), F73..F84 (manufacturing/EOL traceability), F85..F100 (UDS/OTA consistency & V2 flash evolution).
   - **CDI_FLASH rules** — compact rule-set appended after the sprint briefs, mirroring the structure above but tagged CDI_FLASH-001..CDI_FLASH-XX, with traceability to G6..G11 record IDs.
   - **V2-FLASH rules** — evolved flash protocol rules tagged V2-FLASH-001..V2-FLASH-20, mirroring the structure but with manufacturing/EOL traceability, UDS session transitions, power-transient handling, and OTA consistency checks.

4. **Format discipline:** Both the sprint brief schema and the rule-sets follow the exact PROMPT_W7_G5_ASIL_DOMAINS.md frozen master prompt pattern: header block, §1 analysis, §2 scope, §3 record schema (frozen), §4 evidence index, §5 unanswered questions, §6 limitations. New fields are appended at the end of each record — no existing field renamed/removed. Backward compatible with matrices, indices, and checks.

5. **AI-ready meaning:** each `AI-ready guideline` is written as a tool-consumable rule: IF <condition> THEN <rule> WITH <artefact> GATE <approval>. Lesson-learnt is a 15-year field note (what actually fails, what actually works). All guidelines use PowerShell Select-String/Get-Content only (no regex libraries, no external tools).

## 3. Record schema (frozen)

Sprint brief records use the following frozen schema (verified against PROMPT_W7_G5_ASIL_DOMAINS.md §3), with exactly 9 fields in this order:

**Field 1:** ID  
**Field 2:** Topic  
**Field 3:** ASIL-relevant question  
**Field 4:** Domain  
**Field 5:** Target artifact (matrix/artefact/ref)  
**Field 6:** Confidence  
**Field 7:** Unanswered  
**Field 8:** AI-ready guideline IF/THEN/WITH/GATE  
**Field 9:** Lesson learnt  

Each `AI-ready guideline` is written as: `IF <condition> THEN <rule> WITH <artefact> GATE <approval>`

Each `Lesson learnt` is a 1–3 sentence field note (what actually fails, what actually works).

**PowerShell constraint:** All text extraction uses Select-String/Get-Content only. No regex libraries, no external tools.
